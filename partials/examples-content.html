Loading State

This site registers a custom get:apply:loading: method to toggle a CSS class on the receiver during async operations.

This box dims while loading.
View Source 
talkDOM.methods["get:apply:loading:"] = function(el, url, op, cls) {
  el.classList.add(cls);
  return talkDOM.methods["get:apply:"](el, url, op)
    .finally(function() { el.classList.remove(cls); });
};

<style>.is-loading { opacity: 0.5; }</style>

<div receiver="demo6a">This box dims while loading.</div>

<button sender="demo6a get: /partials/demos/hello.html apply: inner loading: is-loading">
  Load with Indicator
</button>

Replace the Receiver Element

Unlike inner, outer replaces the receiver itself. The response keeps the same receiver name so it can be targeted again.

Original receiver element. Load the replacement to swap this whole box.
View Source 
<div receiver="card" accepts="outer">Original card</div>
<button sender="card get: /card.html apply: outer">Replace</button>

<!-- /card.html must return a replacement with receiver="card" -->
<div receiver="card" accepts="outer">New card</div>

Tips & Tricks

A few habits that make message-driven pages easier to maintain.

Choose the apply operation deliberately

inner replaces a receiver’s contents, append adds to a list, text writes literal text, and outer swaps the receiver element.

Use unique receiver names

A message updates every element with that receiver name. Reuse a name when you want coordinated updates; otherwise give each target its own name.

Use pipes for dependencies

A pipe passes one result to the next step. Separate independent work with a semicolon so both chains can start together.

Persist only non-sensitive UI state

Persisted markup is stored as plain text in same-origin local storage. Never put tokens, passwords, or private data there.

Delegate events for changing content

Listen on a stable ancestor such as document when controls may be replaced. talkDOM also bubbles talkdom:done and talkdom:error events.

Keep form bodies explicit

Core post: sends a request without serializing a form. Register a custom method for validated form or JSON payloads.

For arbitrary values, pass arguments directly instead of building a message string:

const notice = document.querySelector('[receiver="notice"]');
await talkDOM.deliver(notice, "text:", [userProvidedValue]);
